dot is built to be used by coding agents as well as people. The repo's
`AGENTS.md` tells an agent the rules; these are the ones that matter to you.

## What an agent may do on its own

- **`dot check`**, **`dot explain`**, **`dot doctor`** and every `--help`:
  they never change anything, and never need a password or Touch ID.
- **Read the repo and these docs.** The site publishes `llms.txt`, the whole
  docs as one file (`llms-full.txt`), and every page as raw Markdown.

## What waits for you

- **`dot apply`**, and anything else that changes the Mac, including
  `dot clone` and `dot fork`.
- **Anything with `sudo`.**
- **`git push`**, since your fork is public.
- **Creating or changing a secret's value.** An agent never reads or prints a
  private key, token or secret value; a project secret only travels through
  pipes (`dot secret`).

## Touch ID

Commands that reach an account through 1Password (`gh`, `vercel`,
`dot auth status`, `dot fork`, `dot secret`, `dot conf`) ask for Touch ID once
per terminal session. Agents usually run each command in a new shell, so a
long task can ask many times. `AGENTS.md` tells them to batch those commands
into one shell call; [Accounts](../04-your-projects/03-accounts/index.mdx)
compares what each login costs.

On a clean Mac, an agent runs the installer with `--yes --no-apply`: it
installs, stops after `dot check`, and shows you what `apply` would change.

## The dot skill

`AGENTS.md` only reaches an agent working inside this repo. The `dot` skill,
in `skills/dot/`, carries the same rules to agents working anywhere else: how
to find `dot`, which commands they may run on their own, which task maps to
which command (`dot clone` instead of `git clone`, `dot secret` instead of a
token in a file, a `config/` line instead of `brew install`), and how to
batch the commands that ask for Touch ID.

It's a standard [Agent Skill](https://skills.sh), so the
[skills CLI](https://github.com/vercel-labs/skills) installs it for Claude
Code, Codex, Cursor and the other agents it supports, straight from GitHub:

```sh
npx skills add rbadillap/dotfiles --skill dot --global
```

It asks which agents to install it for. `npx skills update` brings in a newer
version after you change the skill.

## Claude Code hooks

Claude Code (the CLI and the desktop app's Code tab) reads
`~/.claude/settings.json`. Claude Code writes its own settings there, so dot
only adds hooks to that file and never touches the rest. To add one, put
the script in `config/home/.claude/hooks/` and a `claude hook` line in
`config/claude.conf`; the script is linked into `~/.claude/hooks/`.

```sh
dot check claude     # which hooks are missing
dot apply claude     # add them
```

A new or changed hook takes effect in the next Claude Code session.
