`gh`, the GitHub CLI, needs a login to call GitHub's API: creating repos,
opening pull requests, adding SSH keys. `git push` and `git pull` don't use
it; they go over SSH with the key from 1Password ([1Password and GitHub](../../02-get-started/04-1password-and-github.mdx)).

This guide uses the **token in 1Password** way. The interactive alternative
is at the end, for comparison.

## Requirements

1Password with **Integrate with 1Password CLI** turned on
([1Password and GitHub](../../02-get-started/04-1password-and-github.mdx), step 1).

## 1. Install the CLI

```sh
dot apply packages    # installs what's missing: here, gh
```

This installs `gh` and `op`, from `config/packages.conf`; what's already
installed stays as it is. `op plugin init gh` only works once `gh` exists.

## 2. Create a token (once, ever)

GitHub offers two kinds of personal access token. Pick one:

| Kind              | Creating it                         | Access                   |
|-------------------|-------------------------------------|--------------------------|
| **Fine-grained**  | GitHub's default; permissions picked one by one | Only what you grant |
| **Classic**       | One pre-filled link, below          | Broad scopes             |

Both need GitHub's 2FA when you create them. Either way, copy the token at
the end: it's shown only once, and the next step stores it.

### Fine-grained (what GitHub offers by default)

Open [https://github.com/settings/personal-access-tokens/new](https://github.com/settings/personal-access-tokens/new):

- **Name:** `gh CLI (1Password)`
- **Expiration:** your choice. A date means rotating the token when it
  expires (see *Renewing*).
- **Repository access:** *All repositories*.
- **Repository permissions:** set these to *Read and write*:
  - *Administration* (create repos)
  - *Contents*
  - *Issues*
  - *Pull requests*
  - *Workflows*

  *Metadata* becomes *Read-only* automatically.
- **Account permissions:** set these to *Read and write*. Without them,
  `dot apply github` fails with HTTP 403:
  - *Git SSH keys* (upload your SSH key for authentication)
  - *SSH signing keys* (upload it for commit signing)

Picking permissions one by one is where most of the time goes.

### Classic (fastest)

This link opens the form with the name and every scope already filled in;
just pick an expiration and generate:

[https://github.com/settings/tokens/new?description=gh%20CLI%20(1Password)&scopes=repo,read:org,workflow,gist,admin:public_key,admin:ssh_signing_key](https://github.com/settings/tokens/new?description=gh%20CLI%20(1Password)&scopes=repo,read:org,workflow,gist,admin:public_key,admin:ssh_signing_key)

| Scope                   | Why                                             |
|-------------------------|-------------------------------------------------|
| `repo`                  | Work with your repositories, including private ones |
| `read:org`              | Read organizations; `gh` expects it             |
| `workflow`              | Edit GitHub Actions workflows                   |
| `gist`                  | Create gists                                    |
| `admin:public_key`      | Add your SSH key for authentication             |
| `admin:ssh_signing_key` | Add your SSH key for commit signing             |

## 3. Connect it to gh (once per Mac)

```sh
op plugin init gh
```

It asks three things:

1. **Credential:** choose *Import into 1Password*, paste the token, and save
   it in your built-in personal vault (Personal, or Private on business
   accounts). On a later Mac, choose the item that already exists instead.
2. **Scope:** choose *Use as global default on my system*, so `gh` uses this
   token everywhere. It's the third option: the list starts on *Prompt me
   for each new terminal session*, so move down before pressing Enter.
3. It finishes by printing a command that adds a line to `~/.zshrc`. Skip
   it: dot's shim does that job for every process (step 4).

## 4. Use gh from anywhere (once per Mac)

```sh
dot apply shell
```

`op shim gh` (in `config/shell.conf`) links a shim to
`~/.local/share/dotfiles/shims/gh`, and `config/shell/op.zsh` puts that
folder first on PATH. Every process that runs `gh`, whether your terminal, a
script or an agent, finds the shim, which runs the real `gh` through
`op plugin run`: the token goes into that one process. Open a new terminal so
the PATH applies.

The line that `op plugin init` prints would load `~/.config/op/plugins.sh`,
whose `gh` function only exists in an interactive zsh. If you ran it,
`dot check shell` names that line of `~/.zshrc`; delete it.

What the shim does besides that:

- `gh auth login`, `logout` and `refresh` stop with a message: the login
  lives in 1Password.
- A token in the environment (`GH_TOKEN`, `GITHUB_TOKEN`) that 1Password
  didn't set is ignored with a message, and the token from 1Password is used:
  a cloned repo's `.env`, or a stray `export`, can't change who `gh` acts as.
  1Password set it when `op` starts `gh` directly (`op run -- gh …`) or when
  `DOT_OP_SHIM=gh` comes with it. Set that by hand when `op run` starts a
  script or a shell that then runs `gh`, since `gh`'s parent isn't `op` there:

  ```sh
  DOT_OP_SHIM=gh GH_TOKEN="op://<vault>/<item>/token" op run -- sh -c 'gh …'
  ```

- Messages go to stderr, so `gh … --jq` output stays clean.
- Without the plugin (`op plugin init gh` not run), it runs `gh` unchanged.

Then add the `dotfiles` tag, keeping the one `op` added:

```sh
op item edit "GitHub Personal Access Token" --tags "1Password Shell Plugins,dotfiles"
```

## 5. Check it

```sh
gh auth status
```

It asks for Touch ID, then shows you logged in to github.com with the token
from `GH_TOKEN`. That variable is set by the plugin for that single command;
nothing is written to disk.

## 6. A token for agents (optional)

Your token can do everything you can. An agent, or a script nobody watches,
can get a second token that reaches only the repos it works on.

1. Create a fine-grained token at
   [github.com/settings/personal-access-tokens](https://github.com/settings/personal-access-tokens/new):
   *Only select repositories*, with the repos agents work on. Repository
   permissions: Contents, Issues and Pull requests *Read and write*; Actions
   *Read-only* (Metadata comes with it). No Administration or Workflows.
2. Save it in 1Password as an API Credential named "GitHub Agent Token", in
   your built-in personal vault, with the token in a field named `token` and
   the tag `dotfiles`.
3. Add its reference to `dot.toml`, under `[github]`:

   ```toml
   agent_token = "op://Personal/GitHub Agent Token/token"
   ```

4. Apply it:

   ```sh
   dot apply shell
   ```

`op agent-token gh $github.*` keeps the reference in
`~/.local/share/dotfiles/agent-tokens/gh`. From then on, the shim picks the
token by who runs `gh`:

| Who runs `gh`                                         | Token |
|-------------------------------------------------------|-------|
| You, in a terminal (stdin or stderr is one)           | yours, through the plugin |
| An agent (`AI_AGENT`, `CLAUDECODE`, `CODEX_SANDBOX`, `CURSOR_AGENT` or `GEMINI_CLI` set), even in a terminal | the agent token, through `op run` |
| A script without a terminal, launchd                  | the agent token |

If the agent token fails (the item is gone, 1Password says no), the command
fails: it never falls back to yours. Run what needs your token, such as
`dot apply github` or creating a repo, from your terminal.

This sets a safer default, not a wall: a process that runs as you can still
reach your token, through `op plugin run` or by editing those files, behind
1Password's approval. The token's own limits are what GitHub enforces.

## Friction

| Criterion        | Token in 1Password                          | Interactive login |
|------------------|---------------------------------------------|-------------------|
| Time             | ~10 min to create the token (fine-grained); per Mac: not measured | not measured |
| Browser          | once, to create the token                   | on every Mac      |
| 2FA              | once, when creating the token               | on every Mac, if asked |
| Per machine      | `op plugin init gh` (the shim comes from `dot apply shell`) | the whole login   |
| Expires          | as set when creating the token              | no                |
| Secret on disk   | no                                          | in the macOS Keychain |
| Touch ID         | once per terminal session (each agent command is usually one) | never |

The token is created once; each later Mac repeats steps 1 and 3–5.

## Renewing

If the token has an expiration date, GitHub emails you before it expires.
Regenerate it on GitHub, then replace the value in the 1Password item. Every
Mac picks up the new value on its next `gh` command.

## Alternative: interactive login

```sh
gh auth login --hostname github.com --git-protocol ssh --web
```

It shows a one-time code and opens the browser, where you paste it and
authorize. The token is stored in the macOS Keychain, and this has to be
repeated on every Mac.
