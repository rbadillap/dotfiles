---
title: Stay up to date
description: Pull the latest config, upgrade your packages, and keep dot's own requirements healthy.
---

```sh
dot update        # pull the repo, move the live copy to it, show what would change
dot apply         # apply it, when you're ready
dot upgrade       # newer versions of your packages and tools
dot doctor        # dot's own requirements
dot auth status   # every login dot uses
```

- **`dot update`** fetches your repo from GitHub, moves the
  [live copy](#the-live-copy) to its main branch, and runs `dot check` to
  show what the new version would change. It never applies.
- **`dot upgrade`** upgrades packages and tools to their newest versions
  ([below](#newer-versions)).
- **`dot doctor`** checks what dot itself needs: the Command Line Tools,
  Homebrew, 1Password with its CLI and SSH agent, `gh`, Varlock, `dot.toml`
  (errors, and values missing from it), and the shell setup. Each problem
  comes with its fix. No Touch ID.
- **`dot auth status`** checks each login: the 1Password CLI, `gh`, SSH to
  GitHub, `vercel`, and each AWS organization in `dot.toml`. It asks for
  Touch ID ([Accounts](../04-your-projects/03-accounts/index.mdx)).

## Newer versions

`config/` says which packages you want, not which version, so a new release
never shows up in `dot check`. `dot upgrade` takes care of that:

```sh
dot upgrade         # list what's outdated, then ask
dot upgrade --yes   # upgrade without asking
```

It refreshes Homebrew's package list, then shows each package and tool with
a newer version, one per line:

```text
brew formula gh  2.101.0 → 2.102.0
brew cask slack  4.52.162 → 4.52.178
mise uv  0.12.18 → 0.12.23
```

- **Homebrew:** everything it installed, not only what `config/` lists:
  exactly the list `brew outdated` shows. Homebrew leaves out most apps that
  update themselves, unless one falls behind (Chrome before its own update
  runs). A formula you pinned with `brew pin` stays where it is. Upgrading
  an app may ask for your password.
- **mise:** the global tools, within the versions
  [their config](../03-your-mac/06-languages.mdx) asks for: `node = "24"`
  moves to a newer 24, never to 25, and the previous version stays for a
  day before mise removes it. A project's own versions are that project's
  business.

Without a terminal to ask on and without `--yes`, it lists the upgrades and
exits 1, changing nothing.

## The live copy

What runs on your Mac comes from `~/.local/share/dotfiles/live`, a copy of
your repo at its main branch on GitHub: `~/.zshrc` loads `dot` from it, and
every file dot links into `~` (the `gh` and `vercel` shims, Zed's settings,
Hammerspoon) points into it. Your repo is where you work: a branch you check
out there, or a change you haven't merged, runs nowhere until it's on main
and you run `dot update`. To try a change first, run that copy's `bin/dot`.

`dot update` creates the live copy the first time and only ever moves it
forward along main. `dot check` says when it's behind. If it's missing,
nothing falls back to your repo: `~/.zshrc` says so, and `dot apply` stops
at every setting that needs it until you run `bin/dot update` in the repo.

## Changes you make on the Mac

Some apps edit their own settings files, and dot links those files from the
live copy ([Editor](../03-your-mac/05-editor.mdx)), so a change you make in
the app lands there, and `dot check` names the file. To keep it, bring it
into your repo and merge it:

```sh
git -C ~/.local/share/dotfiles/live diff | git -C ~/code/<you>/dotfiles apply
```

To drop it: `git -C ~/.local/share/dotfiles/live checkout -- <file>`. Until
main has the change, `dot update` leaves the live copy where it is, so
nothing is lost. A preference you change in System Settings shows up in
`dot check` as a difference: put it back with `dot apply`, or change the line
in `config/` to keep it.

## Upstream improvements

Your fork is a normal git repo. To bring in changes from the original, add
it as a remote once and merge when you want:

```sh
dot cd
git remote add upstream git@github.com:rbadillap/dotfiles.git
git pull upstream main
```

Conflicts, if any, will be in `config/`, where your choices differ.
